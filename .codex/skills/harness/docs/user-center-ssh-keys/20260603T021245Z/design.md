# Design

## Goal

Replace the current sidebar password-only entry with a dedicated current-user profile page where users can change their password and manage SSH public keys used for container login.

## Interfaces

### Backend REST API

No API shape changes are required. The frontend will consume the existing endpoints:

- `GET /users/:id/ssh-keys` -> `SshPublicKeyDto[]`
- `POST /users/:id/ssh-keys` with `{ name, keyText }` -> `SshPublicKeyDto`
- `DELETE /users/:id/ssh-keys/:keyId` -> `204`
- `PATCH /users/:id` with `{ password, currentPassword }` -> updated `UserDto`

### Frontend UI

Before:

- Sidebar user block contains a `修改密码` button.
- Clicking it opens `ChangePasswordDialog`, which only supports password updates.

After:

- Sidebar user block contains a `用户中心` link.
- Clicking it navigates to `/profile`.
- The profile page contains two full-width sections:
  - password change form;
  - SSH public key management for the logged-in user.
- SSH key management includes:
  - current key list with name, created time, and a shortened key preview;
  - empty state;
  - add-key form with display name and public key text;
  - delete action per key.

## Data Model Changes

None.

The existing `SshPublicKeyDto` from `@nyabase/common` is sufficient:

```ts
interface SshPublicKeyDto {
  id: string;
  name: string;
  keyText: string;
  createdAt: string;
}
```

## Risks and Trade-Offs

- The profile page consumes a top-level route and is not visible only as an overlay. This matches the updated user request and gives the feature room to grow, at the cost of adding route generation work.
- SSH key lists can grow. Mitigation: keep rows compact and use a constrained list area if needed.
- Adding full add/delete interaction tests could make visual tests more stateful. Mitigation: cover default rendered state visually and rely on React Query invalidation plus existing API wrapper behavior for mutations.
- Backend currently performs schema validation but does not deeply validate OpenSSH key format. This design keeps that behavior unchanged.

## Acceptance Criteria

- Sidebar action reads `用户中心`, not `修改密码`.
- Clicking `用户中心` navigates to `/profile`.
- `/profile` renders a page titled `用户中心`.
- The page includes a password change section with current password, new password, and confirmation inputs.
- The page lists current user's SSH public keys from `/users/:id/ssh-keys`.
- The page allows adding an SSH public key by name and key text via `POST /users/:id/ssh-keys`.
- The page allows deleting a key via `DELETE /users/:id/ssh-keys/:keyId`.
- The SSH section copy states that the keys are used for container SSH login.
- Visual coverage captures `/profile` from an authenticated page.
- No generated `.js`, `.js.map`, `.d.ts`, or `.d.ts.map` files are left under `packages/common/src/**`.

## Out of Scope

- Backend schema or migration changes.
- OpenSSH public key parsing/format validation beyond existing backend schema.
- Admin UI for editing another user's SSH public keys.
- Container SSH protocol, agent, or Dropbear runtime changes.
